PN532 实验排障：从总线到射频.

把模块接通只是开始。按供电、接口、协议、射频和软件恢复分层排查，才能把偶然成功变成可重复的硬件实验。

ON THIS PAGE确认接口选择五层故障定位实验记录一次只改变一个变量安全边界与资料

2017 年那篇 PN532 记录，重点是“把模块接起来并读到响应”。今天回头看，我更想补上实验记录里经常缺失的一半：当它不工作时，如何知道问题在供电、接口选择、主机总线、协议时序，还是射频耦合？

这篇不再重复读卡或复制卡片的操作步骤，而是把 PN532 当成一个嵌入式外设，整理一套适用于自有测试模块和测试卡的排障方法。对 NFC 实验来说，能稳定解释失败，比偶然成功一次更有价值。

先确认你手里的模块到底选了哪种接口

PN532 芯片支持 SPI、I²C 和 HSU（高速 UART）主机接口，但三者是互斥选择：芯片在上电时根据接口配置脚选择当前链路。开发板通常把配置脚引到跳帽或拨码开关上，但不同厂商的板子丝印、默认状态和引脚布局可能不同。

因此，不要只看网上某张接线图就认定自己的板子处于 SPI 或 I²C 模式。先找到对应模块的原理图或用户手册，再核对跳帽状态、主机接线和软件驱动是否一致。NXP 的 PN532 User Manual 明确说明了 SPI、I²C、HSU 三种接口以及上电时的接口选择机制。

把故障定位拆成五层

1. 供电与复位

先检查模块供电是否符合具体 breakout 的规格，主机与模块是否共地，复位脚是否被错误拉低。不要把芯片裸片的电源规格直接套用到所有带稳压器和电平转换的开发板上；应以手头模块的电路和说明为准。若模块有状态灯，它只能提供线索，不能替代电压测量。

2. 接口选择与总线

确认模块的 SPI / I²C / UART 选择与驱动实例一致，再检查主机是否启用了对应总线。I²C 要确认地址扫描结果、上拉和总线是否被其他设备占用；SPI 要核对片选脚和时钟模式；UART 则要核对 TX/RX 交叉、波特率和串口是否已被系统服务占用。不同 breakout 对 IRQ、RSTPD_N 或 H_REQ 的要求也可能不同。

3. 芯片协议是否真的有响应

把“总线能看到设备”和“PN532 协议正常工作”分开。I²C 扫描到地址，不代表命令帧、ACK 和响应帧都正确；SPI 有时钟活动，也不代表片选时序和数据位序正确。建议先运行驱动提供的最小固件版本查询或初始化示例，确认得到完整、可解析的响应，再继续做更复杂的应用。

4. 射频层与天线环境

如果芯片初始化正常，但读卡表现不稳定，再检查射频层：卡片与天线的距离、方向、天线附近的金属、外壳材料、供电噪声和天线调谐都会影响耦合。把卡片贴得更近不一定总能解决问题；先固定位置和方向，再逐项改变条件，才容易定位原因。

5. 软件状态与恢复

记录初始化失败、超时、无目标、协议错误和异常退出等不同状态。若程序超时后直接无限重试，可能把一次短暂故障变成总线长期占用。实验程序应有有限重试、明确的 reset / re-init 路径，以及可观察的错误类别。

建立一份小而够用的实验记录

不需要一开始就做复杂平台。每次测试至少记录以下字段：

字段记录内容目的
设备主机型号、模块版本、天线版本区分硬件差异
链路SPI / I²C / UART、总线参数、复位和 IRQ 配置复现主机通信条件
环境供电、线缆长度、卡片距离和方向识别电气与射频变量
结果成功、超时、无响应、协议错误、初始化失败区分故障阶段
重复性尝试次数、成功次数、重试次数量化稳定性而不是凭感觉

如果要把实验变成一个本地小服务，可以只保存时间、测试编号、模块配置和错误类别。对测试卡使用自定义标签，不必把真实 UID、卡片 dump 或密钥写入日志。这样既能统计成功率，也不会无意间把可识别的卡片数据扩散到备份、截图或公开仓库。

一次只改变一个变量

建议按“已知正常的最小配置 → 更换一项条件 → 重复测试 → 保存结果”的顺序进行。例如：

  1. 使用一块已知正常的模块和一张自己持有的测试卡，先验证最小初始化程序。
  2. 固定接口，只改变线缆长度或供电条件，观察成功率是否变化。
  3. 恢复基线，再改变卡片距离和方向，避免同时修改电气和射频变量。
  4. 最后再把初始化和轮询逻辑放进常驻服务，检查超时、复位和退出后的恢复能力。

每个条件重复多次，比只记录一次“成功”更有意义。若出现偶发失败，应保留失败样本，而不是把它当作噪声删掉。

安全边界和公开资料

NFC/RFID 测试只应针对自己持有或获得明确授权的设备与测试卡。不要读取、复制或公开他人的门禁、支付或身份凭据；不要把原始卡片数据、密钥和可关联到个人的标识上传到公开仓库。

  • NXP PN532 User Manual（UM0701）：接口选择、协议和时序说明。
  • NXP PN532/C1 数据手册：芯片接口与电气规格。
  • Adafruit PN532 Library 文档：I²C、SPI 和 UART 驱动接口。
  • Adafruit PN532 Simple Test：最小初始化与测试示例。

硬件实验的价值不在于堆出更多命令，而在于把每次试验变成可重复、可解释、可安全分享的记录。
